# 6. 开发路线与验收

## P0：可玩闭环

目标：本地或测试服务完成一关完整流程。

任务：Godot 场景、统一关卡 JSON、图片缓存、缩放拖拽、圆形/多边形命中、提示、结算、本地进度；Go API 提供匿名会话、bootstrap、目录、关卡详情、start 和 complete；建立身份、关卡版本、进度、奖励账本和通用幂等表。

验收：不同分辨率命中准确；旋转/刘海屏不遮挡；断网可玩已缓存关卡；重复 complete 不重复奖励；至少 20 个测试关卡可运行。

## P1：内容与多地区

任务：市场解析、远程配置、标签和规则推荐；先完成一个正式市场内容池；管理后台内容审核；AI Worker 基础图+局部编辑+mask；自动差分校验。流水线稳定后再按配置增加中国大陆、美国、日本和全球内容池。

验收：不发版可调整主题权重；同一客户端在不同 market 返回不同首页；任何关卡均可追溯 prompt_version、model、batch 和审核记录；失败内容不能进入 published。

## P2：商业化与数据

任务：激励广告、插屏频控、永久去广告、账号绑定、恢复购买、服务端支付验证、广告奖励幂等；完整事件体系和核心看板。

验收：绑定账号后进度可跨设备恢复；购买可通过商店账号恢复；伪造客户端权益无效；广告奖励重复请求只发一次；可按市场、主题、关卡查看留存、完成率、提示率和收益。

## P3：运营与扩展

任务：每日挑战、节日活动、A/B 测试、灰度发布、质量自动降权、用户主题偏好、国内 Android 渠道适配、Hidden Object 协议预留。

验收：活动可定时开启关闭；低质量关卡自动退出推荐；推荐原因可追踪；新增地区只需添加配置、翻译和内容，不修改玩法代码。

## AI 开发规则

- 每次只实施一个可验收任务，先写测试或验收脚本。
- 不得自行引入微服务、Kubernetes、复杂推荐模型或实时 AI。
- 不确定业务规则时保留配置项和 TODO，不硬编码猜测。
- 修改协议必须同步 schema、服务端校验、客户端解析和迁移说明。
- 所有外部 SDK 必须包裹适配器并提供 mock。
- 每个阶段输出：变更说明、数据库迁移、API 变更、测试结果、风险和回滚方式。
