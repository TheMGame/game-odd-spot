# 1. 产品与范围

> 当前实现差异：下文的“匿名登录”是早期 P0 目标。当前 Godot 客户端要求账号登录，通过账号服务 token 换取游戏 Session；不应据此文档实现自动匿名启动。

## 1.1 产品定位

一款由 AI 持续生产关卡、面向多个国家和地区运营的移动端找茬游戏。用户感知的价值不是“使用了 AI”，而是高质量、持续更新、贴合当地文化偏好的内容。

## 1.2 核心原则

- 一套 Godot 客户端、一套 Go 后端、一套关卡协议。
- 地区、语言、主题、活动、广告频率均由远程配置驱动。
- AI 只负责内容生产和辅助分析，玩法判定、支付、奖励和进度由确定性代码控制。
- AI 生成内容不得直接发布，必须经过自动验证、人工抽检和灰度。
- 首版优先验证留存、关卡质量和广告收益，不先做复杂社交与订阅。

## 1.3 核心循环

首页推荐 → 下载/预载关卡 → 找出差异 → 必要时使用提示或激励广告 → 结算与奖励 → 解锁下一关/每日挑战 → 推荐相似或新主题。

## 1.4 分阶段范围

原始 P0 可玩验证目标：匿名登录、单一内容目录、找茬玩法、缩放拖拽、提示、离线缓存、本地进度、服务端完成幂等和 20 个测试关卡。当前认证实现以账号登录为准。

P1 内容验证：远程配置、规则推荐、CMS、AI Worker、自动质检、人工审核和一个正式市场；验证稳定后再增加其他市场。

P2 商业验证：激励广告、插屏、永久去广告、支付验证、账号绑定、完整埋点与核心看板。

P3 运营扩展：每日挑战、活动、A/B、质量自动降权、中国大陆 Android 渠道和新增市场。正式上线市场建议至少 60 个可用关卡，但不作为 P0 前置条件。

## 1.5 已冻结默认玩法

- 竖屏；左右或上下图片布局由屏幕比例自适应，逻辑坐标始终基于原图。
- 普通关固定 5 个差异；无失败倒计时；重复点击同一差异不计数。
- 提示直接高亮一个尚未找到的差异；每日免费提示次数由远程配置控制。
- 原始规划为 P0 匿名账号；当前客户端采用账号登录，服务端匿名接口仅作为兼容能力保留。
- 永久去广告仅移除强制插屏，保留用户主动触发的激励广告。

## 1.6 暂不进入 MVP

实时生成关卡、开放式 AI 对话、复杂装修系统、PVP、实时排行榜、UGC、订阅、复杂体力系统、多区域数据库。
