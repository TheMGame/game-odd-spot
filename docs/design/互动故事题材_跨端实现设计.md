# 互动故事题材跨端实现设计

## 1. 目标与基准内容

本设计为 `interactive_story` 玩法的实现契约，基准内容是《错位大侦探·雨夜来客》HTML 原型。原型约 2.36 MB，含 35 张 base64 图片、25 个步骤，无音频，交互包括场景叙述、角色对话、选择、热点调查、证据展示、拼图、证据排序和结局。

验收目标：同一份结构化故事数据能由 Admin 配置，经现有服务端发布，在 Web 和微信小游戏播放；图片、背景音乐、逐节点配音均使用远程版本化资源，不执行内容提供者提交的 HTML/JavaScript。

## 2. 核心决策

1. `index.html` 是迁移来源，不是线上运行格式。微信小游戏没有 DOM，直接执行 HTML 无法跨端，也无法安全审核脚本。
2. 故事数据继续保存于关卡 `runtime_json`，玩法标识为 `interactive_story`。
3. Web 与微信使用相同的纯 JavaScript 状态机 `core/story.js`；两端只分别实现 Canvas、资源和音频适配。
4. 图片与音频采用已有资源描述：`asset_id/url/sha256/bytes/content_type`。禁止在发布数据中使用 base64 和本地绝对路径。
5. 故事按节点保存进度。版本升级不覆盖旧版本存档。

## 3. 数据模型

关卡保留通用字段，`assets` 可包含关卡默认音乐，故事内容位于 `story`：

```json
{
  "mode": "interactive_story",
  "assets": {},
  "story": {
    "start_node": "intro",
    "nodes": {
      "intro": {
        "type": "scene",
        "title": "雨夜来客",
        "text": "暴雨封住了道路。",
        "image": {"asset_id": "scene_intro", "url": "https://...", "sha256": "...", "bytes": 1, "content_type": "image/webp"},
        "music": {"asset_id": "music_rain", "url": "https://...", "sha256": "...", "bytes": 1, "content_type": "audio/mpeg"},
        "voice": {"asset_id": "voice_intro", "url": "https://...", "sha256": "...", "bytes": 1, "content_type": "audio/mpeg"},
        "next": "question"
      }
    }
  }
}
```

支持节点：

| 类型 | 主要字段 | 行为 |
|---|---|---|
| `scene` | `title/text/image/music/voice/next` | 场景叙述 |
| `dialogue` | `speaker/text/image/voice/next` | 角色对白 |
| `choice` | `choices[].id/label/next/set` | 分支选择 |
| `hotspot` | `hotspots[].x/y/radius/evidence_id` | 图片调查，坐标为 0～1 |
| `evidence` | `evidence_id/title/text/image/next` | 证据入库 |
| `sequence` | `items/correct_order/next` | 证据链排序 |
| `puzzle` | `image/puzzle.rows/puzzle.cols/next` | 复用块组拼图逻辑 |
| `ending` | `ending_id/title/text` | 完成关卡 |

每个节点可设置 `set` 修改故事变量。第一期状态机保存变量，但 UI 条件表达式留到后续迭代，避免引入可执行表达式。

## 4. 音频规则

- `assets.music`：关卡默认循环音乐。
- `node.music`：进入节点时覆盖背景音乐。
- `node.voice`：进入节点时播放一次，用“音效”偏好控制。
- 浏览器必须在用户首次交互解锁后播放；微信使用 `wx.createInnerAudioContext`。
- 切后台暂停音乐与配音。
- 推荐 MP3/M4A；素材库仍兼容 WAV/OGG。单文件沿用 15 MB 上传限制。
- 当前原型没有声音。迁移时按节点补 `voice`，雨声等循环氛围第一期可合入背景音乐，后续再拆独立 ambient 通道。

## 5. Admin

关卡玩法选择增加“互动故事”。故事编辑器当前提供：

- 通用标题、系列、难度。
- 节点清单与起始节点提示。
- 结构化 JSON 编辑、格式即时校验。
- 草稿和发布。
- 图片、音乐、配音使用素材库上传后返回的完整资源描述。

发布由服务端再次校验：节点类型、起点、跳转目标、选择字段、热点坐标及至少一个结局。后续可在不改变协议的前提下，把 JSON 编辑区升级成流程图和素材选择器。

## 6. Web 与微信运行时

加载流程：

1. 读取 Catalog 和关卡 JSON。
2. `validateStory` 校验本地数据。
3. 用本地存档创建 `StoryRuntime`。
4. 仅加载当前节点图片，进入下一节点后替换；不一次驻留 35 张图片。
5. 节点进入时切换音乐、播放配音。
6. 每次选择、热点、排序或拼图操作后保存快照。
7. 进入 `ending` 后调用现有关卡完成接口和离线同步队列。

Web 使用浏览器图片和 `<audio>`；微信使用下载缓存、Canvas 图片与 InnerAudioContext。两端 Canvas 坐标统一为 1080 逻辑宽度，热点使用图片内部归一化坐标，因此不同屏幕比例不改变命中位置。

## 7. 服务端与目录

- `contracts/level.schema.json` 已加入 `interactive_story`。
- Catalog 的 `content_count` 对故事返回节点数。
- 故事封面优先取 `cover`，旧玩法继续取 `assets.image`。
- 故事没有 `level_differences`，完成接口以零差异关卡完成，继续复用积分、排行榜和幂等机制。
- 素材 URL 仍通过 `/content/` 规范化并由客户端进行 hash 校验。

## 8. 原型迁移步骤

1. 从 HTML 的 `SC` 对象提取 35 个 data URI，转为 WebP/PNG 文件并上传素材库。
2. 把 `S.step === 0..24` 转成故事节点；共享页面片段拆成 `dialogue/hotspot/puzzle/sequence`。
3. 为每个节点补标题、正文、图片描述和跳转。
4. 按台词清单制作配音，上传后填入对应节点 `voice`。
5. 配置雨声/调查背景音乐并在关键节点覆盖。
6. Admin 保存草稿，分别在 Web 和微信真机走通所有路径，再发布。

基准 JSON 见 `contracts/examples/level.valid.interactive-story.json`。其中包含本原型涉及的全部交互类型；替换资源描述并扩充到 25 个节点即可承载完整内容。

## 9. 限制与后续

- 不支持任意 HTML、CSS、外链脚本和 iframe 作为跨端内容。
- 第一版选择项均直接显示；条件分支编辑器、变量表达式和多结局统计后续增加。
- Admin 第一版是 JSON 编辑器；节点流程图、批量配音、字幕时间轴和 HTML 辅助导入属于生产效率迭代。
- 微信真机必须验证音频域名、切后台恢复、弱网续玩、缓存空间和长故事内存峰值。
